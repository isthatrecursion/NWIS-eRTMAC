# Grounded Ask NWIS and validation

Ask NWIS is connected to the backend. No external language model is configured. The local planner converts supported questions into well, formation, event, offset, alignment, evidence, mitigation and alert operations. It retrieves structured records before passages; documents cannot select operations. Responses distinguish FACT, COMPUTED, INFERRED, gaps and sources. Every numeric token is checked against explicitly cited server-side tool outputs or source passages. A verification endpoint rejects drafts containing unsupported numbers or unknown citations. This is numeric provenance verification, not semantic verification of arbitrary prose.

Questions outside the read-only allowlist are refused. Missing records, unresolved aliases, incomplete formation intervals and insufficient transferable evidence produce explicit limitations. Active-well future and held-out records, quarantined events and superseded records are excluded. Query runs record plans, inputs, outputs and rule versions. Historical mitigation quotations are evidence, not operating instructions.

## Validation artifacts

- `storage/gold/representative_pages.pdf` and `labels.json`: 40 independently authored synthetic reference pages, including five scans, five event families, aliases, feet/TVD and ten hard negatives. The Validation page now renders every page, previews normalized event boxes, requires a named independent-human attestation and records reviews separately in `human_reviews.json`. Human sign-off remains at 0/40; this is not a human-certified field gold set.
- `storage/gold/results.json`: extraction precision/recall, depth accuracy, formation correctness, mitigation/outcome exact match, source quote grounding, review fraction and failures. Run `python -m app.gold_set` in backend to rescore; existing annotations are preserved.
- `storage/benchmark/runtime/blind_cases.json`: eight label-free replay cases. Their active-well future events are absent from the runtime repository. Offsets provide the only history.
- `storage/benchmark/evaluation/frozen_predictions.json`: complete predictions saved before the scorer opens separate hidden truth. Results record content hashes, rule versions, hits, misses, false warnings, lead distance, alerts per 1,000 m, overlap, evidence sufficiency and source coverage.
- Four deterministic historical advisory baselines: surface nearest, same-formation equal weighting, static feature similarity and literal document keyword retrieval. They are not equivalent to NWIS's live-corroborated Warning policy; the dashboard states that limitation. Run `python -m app.blind_validation` to repeat.
- `storage/validation/engineering.xml`: actual pytest JUnit output. `python -m app.assurance --junit ../storage/validation/engineering.xml` publishes its measured counts and narrowly scoped safety checks.

The authored eight-case benchmark currently records three NWIS Warnings: two hits, one false warning, one missed severe event and 10 m lead on both hits. This does not establish field accuracy or generalization. The reference extraction set exposes errors rather than claiming perfection; prospective-language candidates require review.

## Safe failure and package

The demo controls reset the same run deterministically. The stale-flow scenario advances to 2480 m with historical Elevated, blocks Warning and explains incomplete live corroboration. Recovery supplies enough fresh samples before allowing Warning. Passing the interval resolves the episode. The polished decision-support vertical remains mud loss; secondary modules retain their limited maturity labels.

`Start-Demo.ps1` binds only loopback, uses `storage/demo/nwis-demo.db`, deterministic seed 121 and prebuilt frontend assets. It copies measured aggregate reports into that separate database. Existing user data is not cleared. A fresh startup creates a new replay; RESET returns the selected run to the initial frame. Wheel caching and no-index installation support offline use on Windows x64 Python 3.12. The checked-in local MP4 backup is an illustrative rendering of recorded API responses, explicitly not a browser screen recording. `python -m app.package_demo` builds a SHA-listed ZIP of explicit assets, excluding user databases and uploaded documents.

The prepared ZIP includes Python 3.12 and initializes a fresh environment from cached wheels when Python is absent from PATH. A fresh extraction was started with one command on a separate port: frontend/API, cited Ask, aggregate reports, stale-flow suppression and local OCR initialization passed. `storage/validation/cold-start.json` records that check. No user database or uploaded files are included in the archive.

Source file reads resolve paths within configured storage. Demo responses use CSP, nosniff and no-store API headers. Extraction has no model/tool agent; uploaded text remains data. APIs control simulations, not rigs. Review, alert transitions and immutable evidence snapshots remain auditable. Public/private classification is metadata, not multi-user access control. A clean isolated Compose build was verified on Docker Desktop 4.93.0: PostgreSQL/PostGIS, migration, seed, API, frontend health and persisted 3D trajectory checks passed; `storage/validation/docker-postgis.json` records the evidence. A bounded local probe also completed 300 reads at 32 workers and 60 deterministic Ask audit writes at 8 workers with zero failures. The resulting `production-assessment.json` says `NOT_PRODUCTION_READY`: authentication/authorization, TLS, external secrets, rate limiting, backup/failover, dependency scanning and penetration testing remain open.

`field_validation.py` accepts externally controlled frozen predictions and later-revealed truth, rejects temporal leakage, scores precision/recall/severe recall/lead distance, and refuses automatic policy changes. The published field report remains `PENDING_EXTERNAL_FIELD_DATA`. The Validation page also provides a timed comprehension-study workflow; it requires five independent participants and 80% correct risk-and-reason responses within 20 seconds. Current participant count is zero.
